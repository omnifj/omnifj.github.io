# 双域名部署：GitHub Pages + 自有服务器

本站同时部署到两个地址：

- `https://omnifj.github.io/` —— GitHub Pages，push 后由 Actions 自动部署
- `https://omnifj.com/` —— 自有服务器，本地构建后手动上传

## 为什么需要两次构建

Hugo 的 `baseURL` 全站唯一，RSS、sitemap、canonical、分享链接等都使用绝对 URL。
直接用同一份产物会导致其中一个域名的链接全部指向另一个域名。

因此采用「一份内容、两次构建」：

| 目标 | baseURL | 构建者 |
|---|---|---|
| GitHub Pages | `https://omnifj.github.io/` | GitHub Actions 自动构建（workflow 中 `--baseURL` 取自 Pages 配置） |
| 自有服务器 | `https://omnifj.com/` | 本地手动构建并上传 |

`hugo.toml` 中的 `baseURL` 保持 `https://omnifj.github.io/` 不变，本地 `hugo server` 预览不受影响。

## 一、GitHub Pages 侧（无需改动）

现有工作流已满足要求，push 到 main 即自动更新 `omnifj.github.io`。

**注意**：

- 不要创建 `static/CNAME`
- 不要在仓库 Settings → Pages 中填写 Custom domain
- 否则 GitHub 会尝试为 `omnifj.com` 签发证书并产生冲突

## 二、自有服务器侧

### 1. DNS 配置

在域名服务商处将 A 记录指向**你的服务器 IP**（不是 GitHub Pages 的 IP）：

| 类型 | 主机记录 | 值 |
|---|---|---|
| A | @ | 你的服务器 IP |
| A | www | 你的服务器 IP（可选） |

### 2. 本地构建（Windows PowerShell）

```powershell
# 在仓库根目录执行
hugo --minify --baseURL "https://omnifj.com/"
```

产物在 `public/` 目录，其中的绝对链接均指向 `omnifj.com`。

### 3. 上传到服务器

`public/` 内的**所有文件**上传到 Web 根目录（如 `/var/www/omnifj.com`）。

方式一：scp（Windows 自带 OpenSSH 客户端）

```powershell
scp -r .\public\* user@<服务器IP>:/var/www/omnifj.com/
```

方式二：WinSCP 等图形化工具，将 `public/` 整个拖入 Web 根目录。

方式三：如果服务器有 rsync（通过 WSL 或 Git Bash 执行），增量上传最快：

```bash
rsync -avz --delete ./public/ user@<服务器IP>:/var/www/omnifj.com/
```

`--delete` 保证删除服务器上已不存在的旧文件，保持完全一致。

### 4. Nginx 配置示例

```nginx
server {
    listen 80;
    server_name omnifj.com www.omnifj.com;
    root /var/www/omnifj.com;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    gzip on;
    gzip_types text/css application/javascript application/xml image/svg+xml;
}
```

HTTPS 用 certbot 一键签发：

```bash
sudo certbot --nginx -d omnifj.com -d www.omnifj.com
```

## 三、一键脚本（可选）

将以下内容保存为 `deploy-server.ps1`（仓库根目录，已建议加入 .gitignore 或替换占位符后使用）：

```powershell
$SERVER = "user@<服务器IP>"      # SSH 用户和地址
$WEBROOT = "/var/www/omnifj.com" # 服务器 Web 根目录

hugo --minify --baseURL "https://omnifj.com/"
if ($LASTEXITCODE -ne 0) { exit 1 }

scp -r .\public\* "${SERVER}:${WEBROOT}/"
Write-Output "已部署到 https://omnifj.com/"
```

以后发布到服务器的流程：

```powershell
# 1. push 更新 GitHub Pages（自动）
git add -A; git commit -m "new post"; git push

# 2. 一键更新自有服务器
.\deploy-server.ps1
```

## 四、验证清单

每次部署后检查：

- [ ] `curl -I https://omnifj.github.io/` 返回 200
- [ ] `curl -I https://omnifj.com/` 返回 200
- [ ] 两边首页均显示最新文章
- [ ] `https://omnifj.com/index.xml` 中链接以 `https://omnifj.com/` 开头
- [ ] `https://omnifj.github.io/index.xml` 中链接以 `https://omnifj.github.io/` 开头

## 五、后续升级路径

如果嫌手动上传麻烦，可升级为 Actions 自动 rsync 到服务器：

1. 服务器创建专用部署用户和 SSH 密钥对
2. 私钥存入仓库 Secrets（`Settings → Secrets and variables → Actions`）
3. 在 `hugo.yaml` 中增加第二个 build（baseURL 为 omnifj.com）+ rsync 部署 job

需要时再进行此改造即可，文档见 `03-发布流程.md`。
